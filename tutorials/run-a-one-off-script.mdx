title: Run a one-off script and collect its output
description: Push a small script into a sandbox, run it once, and pull back its output — the CLI's way to do a one-off batch run
---

Push a small script into a sandbox, run it once, and pull back its output. Tyto's REST/SDK layer has a `jobs` concept for scheduled and async batch work (see [Jobs](/concepts/jobs)), but the CLI has no equivalent command group — this tutorial shows the direct alternative: upload, run, download, done. Every command below uses the `bonya-dev` template; if you haven't installed the CLI or logged in yet, start with the [Quickstart](/quickstart).

<Steps>
  <Step title="Create a sandbox">
    ```shell
    tyto create batch --template bonya-dev
    ```

  <Step title="Write the script locally, then upload it">
    `fs upload` sends exactly one file's bytes per call, which is all a single script needs (see [Files](/concepts/files)).

    ```shell
    tyto fs upload batch ./report.sh /workspace/report.sh
    ```

    <div style={{background: "#171717", borderRadius: "5px", color: "white", fontFamily: "SFMono-Regular, Monaco, Menlo, Consolas, monospace", fontSize: "13px", lineHeight: "20px", padding: "14px 18px", whiteSpace: "pre-wrap", overflowX: "auto"}}>
    <span style={{color: "#626262"}}>Uploaded /tmp/report.sh to /workspace/report.sh</span>
    </div>
  </Step>

  <Step title="Make it executable">
    ```shell
    tyto exec batch -- chmod +x /workspace/report.sh
    ```

    `chmod` prints nothing on success — no output block for this one.
  </Step>

  <Step title="Run it">
    ```shell
    tyto exec batch -- sh -c '/workspace/report.sh > /workspace/report.log 2>&1'
    ```

    Redirecting to a file remotely means the CLI itself prints nothing (`exec`'s own exit code mirrors the remote command's exactly), but the file now holds the run's output:

    ```shell
    tyto fs read batch /workspace/report.log
    ```

    ```shell
    tyto fs download batch /workspace/report.log ./report.log
    ```
