Start a long-running process in a managed session, disconnect from it on purpose, and reattach later — even after the sandbox has suspended and resumed. This is the one thing plain `exec` can't do: a managed session outlives your connection (see [Sessions](/concepts/sessions)). Every command below uses the `bonya-dev` template; if you haven't installed the CLI or logged in yet, start with the [Quickstart](/quickstart).

  <Step title="Start a managed session">
    A simple loop stands in for any long-running process — a dev server, a queue worker, anything you'd otherwise leave running in a terminal you don't want to keep open.

    ```shell
    tyto session create worker watcher -- sh -c 'i=0; while true; do i=$((i+1)); echo "tick $i"; sleep 5; done'
    ```

  <Step title="What suspend and resume look like">
    A sandbox suspends automatically after enough inactivity, and resuming is implicit the next time you reach it (see [Sandboxes](/concepts/sandboxes)). This particular session won't trigger that on its own — a detached session's own output still counts as activity and defers idle suspend, so a `tick`-every-5-seconds loop like `watcher` keeps the sandbox awake by design (see [Sessions](/concepts/sessions)). A quieter detached session (or the sandbox sitting untouched entirely) would suspend on its normal schedule instead.

    Either way, listing sessions on a suspended sandbox doesn't wake it — you're served from a snapshot taken the moment it suspended, and the output says so explicitly:

    ```shell
    tyto session list worker
    ```

  <Step title="Reattach">
    Attaching to a suspended sandbox's session wakes it — the process was never stopped, it just wasn't being watched.

    ```shell
    tyto session attach worker watcher
    ```
