Every sandbox operation on `client.sandboxes` also has a flat form
directly on `Tyto` — `client.createSandbox(...)`, `client.getSandbox(id)`,
`client.getSandboxByName(name)`, `client.listSandboxes()`,
`client.deleteSandbox(id)`, `client.resumeSandbox(id)` — for callers who'd
rather call a verb than navigate a namespace. Both spellings are the same
implementation.

Sessions, previews, and snapshots have flat forms too (`client.createSession(sandboxId, name, cmd)`,
`client.createPreview(sandboxId, port)`, `client.createSnapshot(sandboxId)`,
and so on), but each does a `getSandbox()` first and then delegates — one
extra round trip compared to already holding a `Sandbox` handle. Prefer
`sandbox.sessions.create(...)` (or the equivalent) when a `Sandbox` is
already in hand; reach for the flat form when all you have is an id.

## Create sandboxes

```ts
import { Tyto, Wait } from "@bonya-ai/tyto";

const client = new Tyto();
const sandbox = await client.sandboxes.create({
  template: "ubuntu-24.04",
  wait: Wait.READY,
  idempotencyKey: "create-job-123",
});
```

`client.sandboxes.create(options)` returns a `Promise<Sandbox>`.

| Option | Type | Description |
|---|---|---|
| `template` | `string` | Required, non-empty. |
| `version` | `string` | Template version. Server default when omitted. |
| `wait` | `Wait \| "ready" \| "none"` | Defaults to `Wait.READY`. |
| `idempotencyKey` | `string` | Generated and reused for transport retries if omitted. |
| `name` | `string` | Optional display name, at most 80 bytes. Server generates a friendly one when omitted. Names are not unique. |

`Wait.READY` (or `"ready"`) asks the service to return a running sandbox —
`lastObservedStatus === Status.RUNNING`. `Wait.NONE` (or `"none"`) returns
as soon as the service accepts the request — `lastObservedStatus ===
Status.CREATING`.

If create exhausts its deadline, the SDK throws `SandboxCreationTimeoutError`,
which carries the `idempotencyKey` used so you can retry the same creation
rather than starting a second sandbox.

Sandbox fields: `sandbox.id`, `.operationId`, `.template`, `.version`,
`.lastObservedStatus`.

## Get, list, and get by name

```ts
const sandbox = await client.sandboxes.get("sbx_123");

import { Status } from "@bonya-ai/tyto";

for await (const summary of client.sandboxes.list({
  states: [Status.RUNNING, Status.SUSPENDED],
  limit: 20,
})) {
  console.log(summary.id, summary.lastObservedStatus);
}

const byName = await client.sandboxes.getByName("web-server");
```

`get(sandboxId)` requires a non-empty id and returns a usable `Sandbox`
handle. It does **not** explicitly resume the sandbox — exec and
filesystem calls are what wake a suspended one.

`list(options)` returns an `AsyncIterableIterator<SandboxSummary>` and
pages as you iterate. `limit: 0` yields nothing without an RPC. `options.name`
filters to sandboxes carrying an exact display name (names aren't unique,
so this can still match more than one). Valid `states` filters are
`Status.CREATING`, `RUNNING`, `SUSPENDING`, `SUSPENDED`, `RESUMING`, and
`FAILED` — `Status.DELETED` is not a valid filter. A `SandboxSummary` has
`id`, `operationId`, `template`, `version`, `lastObservedStatus`,
`failureCode`, `failureMessage` — it cannot run `exec`; call `get(summary.id)`
first.

`getByName(name)` resolves a display name to a single sandbox. Names are
not unique: if more than one sandbox carries the name, it throws rather
than picking one (a later `delete()` could otherwise destroy the wrong
sandbox). If none match, it throws `SandboxNotFoundError`.

## Delete and cleanup

```ts
const result = await sandbox.delete();
console.log(result.sandboxId, result.alreadyDeleted);
```

`sandbox.delete()` returns `DeleteResult { sandboxId, alreadyDeleted }`.
Calling it again on the same `Sandbox` object is local and idempotent — no
second RPC. There is no automatic cleanup on scope exit; use `try`/`finally`.

## Resume

```ts
const resume = await sandbox.resume({ idempotencyKey: "resume-job-123" });
console.log(resume.sandboxId, resume.lifecycleOperationId, resume.alreadyRunning);
```

`sandbox.resume(options)` returns `ResumeResult { sandboxId,
lifecycleOperationId, alreadyRunning }` and updates the sandbox's private
exec endpoint/capability, setting `lastObservedStatus` to `Status.RUNNING`.
`resume()` on a failed sandbox throws `SandboxFailedError` locally, before
any RPC.

Explicit resume is different from automatic wake: `get()` never calls
`resume()`, and ordinary exec/filesystem calls don't make a public
`ResumeSandbox` RPC — they hit the sandbox's guest endpoint directly, and
the service may wake it behind that route.

## Exec vs execStream

`exec()` buffers output and resolves once the process exits — good for
short, bounded commands. `execStream()` yields events as they happen —
use it for large output, long-running commands, interactive stdin, or
cancellation. Both are one-shot: the remote process ends when the call (or
stream) ends. This is different from [managed sessions](#managed-console-sessions),
which keep running after you disconnect.

### Buffered exec

```ts
const result = await sandbox.exec(
  ["python3", "-c", "import os; print(os.environ['MODE'])"],
  { env: { MODE: "development" }, cwd: "/workspace", timeout: 10 },
);

console.log(result.stdout, result.stderr, result.exitCode, result.ok);
```

```ts
sandbox.exec(command, {
  env,
  cwd,
  tty,
  cols,
  rows,
  timeout,
  check,
  input,
}): Promise<ExecResult>
```

`command` is either a `string` (run as `["/bin/sh", "-c", command]`) or a
non-empty `readonly string[]` with no empty entries. `env` overlays string
env vars (keys can't contain `=` or NUL). `cwd` sets the remote working
directory. `input` is a `string` or `Uint8Array` written to stdin before
it's half-closed — buffered `input` requires `tty: false`.

`ExecResult` exposes `stdoutBytes`/`stderrBytes` (`Uint8Array`),
`stdout`/`stderr` (UTF-8 getters), `exitCode`, `signaled`, `signal`,
`ok` (`exitCode === 0 && !signaled`), and `toString()` (same as `.stdout`).

`check: true` calls `result.check()` before returning; on a non-ok result
it throws `ExecFailedError`, with the original result at `error.result`.

### Streaming exec

```ts
import { Exit, Stderr, Stdout } from "@bonya-ai/tyto";

const session = sandbox.execStream(["bash", "-lc", "echo out; echo err >&2"]);
try {
  for await (const event of session) {
    if (event instanceof Stdout) process.stdout.write(Buffer.from(event.data));
    else if (event instanceof Stderr) process.stderr.write(Buffer.from(event.data));
    else if (event instanceof Exit) console.log("exit:", event.exitCode);
  }
} finally {
  session.close();
}
```

`execStream(command, { env, cwd, tty, cols, rows, timeout })` returns a
session that is an async iterable of `Stdout`, `Stderr`, and `Exit`
events. Write stdin with `session.write(data: Uint8Array)`, close it with
`session.closeStdin()` (idempotent). `session.cancel()` is idempotent and
sends a cancel frame when possible; `session.close()` cancels an
unfinished session. If iteration reaches the session deadline before the
next event, the SDK cancels the remote exec and throws `TimeoutError`.

### TTY exec

Set `tty: true` for terminal semantics — stdout and stderr share the
terminal stream, so the SDK returns terminal output as `stdout` and leaves
`stderr` empty. Default dimensions are 80x24 (sent on the wire as
`cols: 0, rows: 0`). Provide both `cols` and `rows` together to override —
each must be an integer from 1 through 512, and both require `tty: true`.
Buffered `input` isn't allowed with `tty: true`; use `execStream()` and
`session.write(...)` instead. Resize an active TTY stream with
`session.resize({ cols, rows })`.

## Managed console sessions

Every `Sandbox` has `sandbox.sessions`, a `SandboxSessions` for named,
persistent command sessions that **outlive the client connection**. This
is the key distinction from `execStream()`: an exec process dies when its
stream closes, but a managed session keeps running detached, and you can
reattach later — even after the sandbox warm-suspends and resumes — and
replay what it produced while nobody was watching. Use `exec`/`execStream`
for one-shot commands; use `sessions` for long-lived terminals like dev
servers you want to detach from and come back to.

```ts
const info = await sandbox.sessions.create("server", ["bash"], { cols: 120, rows: 40 });

const session = await sandbox.sessions.attach("server");
session.write(new TextEncoder().encode("npm run dev\n"));
session.resize({ cols: 140, rows: 45 });
for await (const event of session) {
  // ...
}
session.detach();

const list = await sandbox.sessions.list();
for (const info of list) console.log(info.name, info.status);

await sandbox.sessions.kill("server");
```

**Create** — `sessions.create(name, command, { env, cwd, cols, rows, replace })`.
`name` must match `^[a-z][a-z0-9-]{0,31}$`. `command` is a non-empty array
of non-empty strings (no shell-string convenience like `exec()`). Creating
over an existing record throws `SessionExistsError` unless `replace: true`
— and even then, only a terminal record (exited/killed/failed) is
replaced; a running or attached session is never replaced. Returns
`Promise<SessionInfo>`.

**List** — `sessions.list()` returns a `SessionList`: an immutable,
iterable sequence of `SessionInfo` that also carries `sandboxSuspended:
boolean`. Listing works on a suspended sandbox without waking it.

**Attach** — `sessions.attach(name, { cols, rows, maxReplayBytes })`
returns `Promise<SessionStream>`, resolved once admitted. `session.info`,
`.replayedBytes`, `.historyDropped` describe the bounded replay from while
you were detached (the replay ring is 1 MiB). Attaching preempts any other
attached client — the loser gets `SessionEnded(SessionEndedReason.TAKEOVER)`.
Attaching to a suspended sandbox's session wakes it.

Stream events: `Stdout { data }` (merged output — sessions are TTY-only,
no separate stderr), `Exit { exitCode, signaled, signal }`, `SessionEnded
{ reason }` (`DETACHED` or `TAKEOVER`), `SessionOutputDropped { droppedBytes }`
(client reading too slowly; doesn't end the attach).

`session.write(data)`, `session.resize({ cols, rows })` (1–512 per
dimension), `session.detach()` (ends gracefully, process keeps running),
`session.close()` (calls `detach()` if still open).

**Kill** — `sessions.kill(name, { signal, graceMs })` signals the
process group (default `TERM`), escalating to `SIGKILL` after `graceMs`
(default 5000ms). Returns `Promise<SessionInfo>`, but exit info isn't
guaranteed on that response — `kill()` doesn't wait for the guest to reap
the process, so a `list()` shortly after is the reliable way to see the
final exit code. Killing an unknown name throws `SessionNotFoundError`.

`SessionInfo`: `name`, `command`, `workingDir`, `status`, `attached`,
`startedAt`, `lastActivityAt`, `endedAt`, `exit`. `SessionStatus` values:
`UNSPECIFIED`, `STARTING`, `IDLE`, `ATTACHED`, `EXITED`, `KILLED`, `FAILED`.

A session's process never blocks idle suspend by itself — only an
*attached* stream does. A quiet, detached session lets the sandbox
warm-suspend and survives the resume with process and replay buffer
intact.

## Files

Every `Sandbox` has `sandbox.files`, a `SandboxFiles`:

```ts
await sandbox.files.write("/workspace/message.txt", "hello\n");
const payload = await sandbox.files.read("/workspace/message.txt");

await sandbox.files.upload("local-input.bin", "/workspace/input.bin");
await sandbox.files.download("/workspace/input.bin", "local-output.bin");

const entries = await sandbox.files.list("/workspace");
const info = await sandbox.files.stat("/workspace/message.txt");

await sandbox.files.mkdir("/workspace/output");
await sandbox.files.move("/workspace/message.txt", "/workspace/output/message.txt");
await sandbox.files.remove("/workspace/output", true);
```

| Method | Signature |
|---|---|
| `read` | `(path: string) => Promise<Uint8Array>` |
| `write` | `(path: string, data: Uint8Array \| string) => Promise<void>` |
| `upload` | `(localPath: string, remotePath: string) => Promise<void>` |
| `download` | `(remotePath: string, localPath: string) => Promise<void>` |
| `list` | `(path: string) => Promise<FileInfo[]>` |
| `stat` | `(path: string) => Promise<FileInfo>` |
| `mkdir` | `(path: string) => Promise<void>` |
| `remove` | `(path: string, recursive?: boolean) => Promise<void>` |
| `move` | `(source: string, destination: string) => Promise<void>` |

`read()` buffers the whole file and throws `FilesystemLimitError` before
exceeding `filesystemReadLimit`. `write()` streams in 64 KiB chunks
through a guest-side temp file and publishes atomically; a symlink at the
final path is not followed. `upload()`/`download()` stream in 64 KiB
chunks; `download()` uses a temp file, fsync, and atomic rename. `list()`
returns immediate children sorted by name, or throws — no partial results.
`stat()` returns lstat-style metadata (a final symlink is reported as a
symlink, not followed). `move()` is same-filesystem, atomic, no-overwrite
— cross-filesystem throws `CrossFilesystemMoveError`, existing destination
throws `RemoteFileExistsError`. `remove(path, true)` recurses without
following symlinks and is not atomic.

`FileInfo` is immutable: `path`, `name`, `kind` (`FileKind.FILE` /
`DIRECTORY` / `SYMLINK` / `OTHER`), `size`, `mode`, `modifiedAt`.

## Preview URLs

A preview publishes one guest port at an HTTPS URL a browser can open. The
server must bind a port in 1024–65535; privileged ports are never
previewable.

```ts
const preview = await sandbox.previews.create(3000, { name: "web" });
console.log(preview.url); // https://pv-<26 chars>.preview.tyto.run

await sandbox.previews.list();
await sandbox.previews.delete(preview.id);
```

A token-mode preview needs the sandbox's capability, and a URL isn't a
safe place to leave one. `sandbox.previews.browserUrl(preview)` produces a
single-use entry point: the gateway validates the token, trades it for a
host-scoped `HttpOnly` cookie, and redirects without the token in the URL.
It throws on a public preview, which has no token to exchange.

```ts
import { PreviewAuth } from "@bonya-ai/tyto";

const publicPreview = await sandbox.previews.create(8080, { auth: PreviewAuth.PUBLIC });
```

`PreviewAuth.PUBLIC` means anyone with the URL reaches the service, no
credential — the only protection is the 26 random characters in the
hostname. `TOKEN` is the default; an omitted `auth` never yields a public
URL.

`create()` returns a fresh capability and the SDK stores it on the sandbox
automatically (the preview scope is newer than a sandbox's original
token). If you're holding a capability elsewhere, refresh it explicitly
with `sandbox.reissueCapability()`.

Traffic to a preview URL wakes a suspended sandbox; the first request
after suspend pays resume latency and may return `503` with `Retry-After`.

## Snapshots

<Note>
Snapshots exist only through the SDKs (and the `tyto` CLI) over gRPC —
there is no public REST endpoint for creating or deleting them.
</Note>

```ts
const snapshot = await sandbox.snapshot({ idempotencyKey: "snapshot-job-123" });
console.log(snapshot.id, snapshot.sourceSandboxId);

await snapshot.delete();
await snapshot.delete(); // local no-op
```

`sandbox.snapshot(options)` returns `Promise<Snapshot>`. If
`idempotencyKey` is omitted, the SDK generates and reuses one for
transport retries; the same key against the same source sandbox returns
the same snapshot identity on idempotent replay.

Snapshot create requires a running source sandbox: a locally deleted or
observed-deleted sandbox throws `SandboxDeletedError`, a failed one throws
`SandboxFailedError`, a suspended one throws `SandboxSuspendedError`.

`snapshot.delete()` resolves to `void` and is idempotent on the same
object. A snapshot has its own identifier — you can delete it after
deleting the sandbox that produced it.

## Error handling

All SDK exceptions inherit from `TytoError` (itself extending `Error`),
exposing `message`, `sandboxId`, `operationId`, `idempotencyKey`.

```ts
import { AuthenticationError, SandboxNotFoundError } from "@bonya-ai/tyto";

try {
  await client.sandboxes.get("sbx_123");
} catch (error) {
  if (error instanceof AuthenticationError) {
    console.log("check BONYA_API_KEY");
  } else if (error instanceof SandboxNotFoundError) {
    console.log("sandbox does not exist or is not visible");
  } else {
    throw error;
  }
}
```

| Error | Meaning |
|---|---|
| `AuthenticationError` | Invalid or rejected API key. |
| `InvalidRequestError` | Invalid local arguments or invalid service response. |
| `SandboxNotFoundError` | Sandbox missing, deleted, or not visible to the key. |
| `SandboxDeletedError` | Operation can't run — sandbox is deleted. |
| `SandboxSuspendedError` | Operation reported a suspended sandbox. |
| `SandboxBusyError` | Service rejected a lifecycle operation as busy. |
| `SandboxFailedError` | Operation can't run — sandbox failed. |
| `SandboxCreationFailedError` | Create reached a failed terminal state. |
| `SandboxCreationTimeoutError` | Create deadline expired. |
| `CapabilityRejectedError` | Guest capability rejected and couldn't be refreshed. |
| `SessionExistsError` | `sessions.create()` targeted a name with a non-replaceable record. |
| `SessionNotFoundError` | `sessions.attach()`/`.kill()` named a session that doesn't exist. |
| `FilesystemError` | General filesystem failure. |
| `RemoteFileNotFoundError` | Remote file or directory missing. |
| `RemoteFileExistsError` | Remote destination already exists. |
| `CrossFilesystemMoveError` | Remote move crosses filesystems. |
| `FilesystemLimitError` | Client or service filesystem size/frame limit. |
| `ExecFailedError` | `ExecResult.check()` or `check: true` saw a non-ok result. |
| `TimeoutError` | Operation deadline expired. |
| `ConnectionError` | Retryable transport failure exhausted retries. |
| `ServiceError` | Service or unexpected transport failure not covered above. |

The SDK redacts API keys, capabilities, and selected operation identifiers
from mapped service error messages, and replaces path-like substrings with
`[redacted-path]`.

## Resource cleanup

There's no automatic cleanup on scope exit — use `try`/`finally`:

```ts
const client = new Tyto();
try {
  const sandbox = await client.sandboxes.create({ template: "ubuntu-24.04" });
  try {
    const session = sandbox.execStream(["cat"]);
    try {
      session.write(new TextEncoder().encode("hello\n"));
      session.closeStdin();
      for await (const event of session) {
        // ...
      }
    } finally {
      session.close();
    }
  } finally {
    await sandbox.delete();
  }
} finally {
  client.close();
}
```

- `Tyto.close()` closes cached channels and is idempotent.
- `sandbox.delete()` affects the remote sandbox and updates the local
  handle to `Status.DELETED`; idempotent on the same object.
- Closing an unfinished `execStream()` session cancels the remote exec.
- Closing an unfinished `sessions.attach()` stream detaches the guest
  process rather than killing it — it keeps running.
- `snapshot.delete()` deletes the remote snapshot and is a local no-op
  when repeated.

For intentionally persistent sandboxes, don't delete on scope exit — store
`sandbox.id`, close the client, and reconnect later with
`client.sandboxes.get(id)`.
