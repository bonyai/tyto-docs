---
title: Expose a preview
description: Publish a port running inside a sandbox as an HTTPS URL
---

If your sandbox is running a dev server or API on some port, a preview turns that port into an HTTPS URL a browser can open. See [Previews](/concepts/previews) for the full field reference; this guide walks through creating one, choosing an auth mode, and cleaning up.

## Create a preview

<CodeGroup>
```shell cURL
curl -s -X POST "https://api.tyto.run/v1/sandbox/$SANDBOX_ID/previews" \
  -H "Authorization: Bearer $BONYA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"port": 3000, "name": "web"}'
```

```shell CLI
tyto preview create $SANDBOX_ID 3000 --name web
```

```ts TypeScript
const preview = await sandbox.previews.create(3000, { name: "web" });
console.log(preview.url); // https://pv-<26 chars>.preview.tyto.run
```

```python Python
preview = sandbox.previews.create(3000, name="web")
print(preview.url)
```

```go Go
preview, err := sandbox.Previews.Create(ctx, 3000, tyto.CreatePreviewOptions{Name: "web"})
fmt.Println(preview.URL)
```
</CodeGroup>

`port` must be 1024–65535 — privileged ports are never previewable. Create returns `201` with the created preview plus a `capability_jws` — that token is returned **only on create**, never again from list, so hold onto it if you need the token-mode exchange below.

## Token vs. public auth

`auth_mode` (REST) / `auth` (SDK) is one of two values:

- **`token`** (default) — access is gated by a one-time browser exchange (below). This is what you want for anything not meant to be open to the internet.
- **`public`** — anyone with the URL can view it, no credential at all. The only thing protecting a public preview is the 26 random characters in its hostname. Use this deliberately, for demos or sharing outside your organization — not as the default.

<CodeGroup>
```shell cURL
curl -s -X POST "https://api.tyto.run/v1/sandbox/$SANDBOX_ID/previews" \
  -H "Authorization: Bearer $BONYA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"port": 8080, "auth_mode": "public"}'
```

```shell CLI
tyto preview create $SANDBOX_ID 8080 --auth public
```

```ts TypeScript
import { PreviewAuth } from "@bonya-ai/tyto";

const publicPreview = await sandbox.previews.create(8080, { auth: PreviewAuth.PUBLIC });
```

```python Python
public = sandbox.previews.create(8080, auth=PreviewAuth.PUBLIC)
```
</CodeGroup>

The CLI marks public preview URLs in its output as a reminder of what you just did.

## The token-mode browser exchange

In `token` mode, a browser needs to trade the `capability_jws` for a session cookie once before it can view the preview. At a high level: navigate to `preview.url` with `?bonya_token=<capability_jws>` appended, and Roxy (the preview proxy) validates the token, sets a host-scoped `Secure`/`HttpOnly` cookie, and redirects to the same URL with the token stripped — before any guest content renders. See [Previews](/concepts/previews#the-token-mode-browser-exchange) for the exact mechanics.

You don't have to build that URL by hand — the TypeScript, Python, and Go SDKs each expose a helper that does it for you:

<CodeGroup>
```ts TypeScript
const browserUrl = sandbox.previews.browserUrl(preview);
// open browserUrl in a browser — one-time entry point
```

```python Python
browser_url = sandbox.previews.browser_url(preview)
```

```go Go
browserURL := sandbox.Previews.BrowserURL(preview)
```
</CodeGroup>

This throws/raises/errors if called on a public preview, since there's no token to exchange.

<Warning>
Don't store `capability_jws` in a URL, log, or anywhere durable beyond the single navigation described above — it's a bearer credential for the preview.
</Warning>

## List and delete

<CodeGroup>
```shell cURL
curl -s "https://api.tyto.run/v1/sandbox/$SANDBOX_ID/previews" \
  -H "Authorization: Bearer $BONYA_API_KEY"

curl -s -X DELETE "https://api.tyto.run/v1/sandbox/$SANDBOX_ID/previews/$PREVIEW_ID" \
  -H "Authorization: Bearer $BONYA_API_KEY"
```

```shell CLI
tyto preview list $SANDBOX_ID
tyto preview delete $SANDBOX_ID $PREVIEW_ID
```

```ts TypeScript
await sandbox.previews.list();
await sandbox.previews.delete(preview.id);
```

```python Python
sandbox.previews.list()
sandbox.previews.delete(preview.id)
```
</CodeGroup>

List never includes `capability_jws` — only create does. Delete is idempotent and deliberately doesn't distinguish "already deleted" from "belongs to another organization," so it always returns `204`.
